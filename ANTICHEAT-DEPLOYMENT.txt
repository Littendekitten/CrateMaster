CRATEMASTER — SERVER-AUTHORITATIVE ECONOMY / KITTYGEM CRATE

WHAT CHANGED
- KittyCoins, KittyGems, player inventories, Index discoveries and Index milestones are written by the Render server using Firebase Admin SDK transactions.
- Browser Firestore writes are limited to equipped owned items and safe preferences (username, hotbar, sensitivity, volume and bloom).
- Selling is validated server-side. Limited guns require an exact item-name confirmation that is checked again by the server.
- Normal crate and Gem Crate rolls, charges, drops, Index milestones and the 5% completed-normal-Index bonus are generated and committed server-side.
- The Gem Store is now a Gem Crate, costing 25 KittyGems per opening. Odds: Common 50%, Rare 25%, Epic 15%, Legendary 8%, GEM rank 2%.
- Run payouts, XP, kills, best wave and runs are updated by the server. A run ticket is issued on start; rewards are capped against server-measured elapsed time, possible spawns and a maximum kill rate.
- Existing player balances and inventories are preserved by the bootstrap migration. Missing fields are initialized and owned weapons are added to the Index once.

RENDER ENVIRONMENT
Keep these existing environment variables configured in Render:
  FIREBASE_SERVICE_ACCOUNT = complete Firebase service-account JSON
  FIREBASE_DATABASE_URL = your Realtime Database URL

Do not put the service-account JSON in the website or commit it to GitHub. It must remain a secret in Render.

FIREBASE FIRESTORE RULES
Copy the entire firestore.rules file from this package into Firebase Console > Firestore Database > Rules, then Publish.
These rules intentionally deny browser writes to coins, gems, XP, kills, best wave, runs, guns, skins, Index fields and transaction receipts. The Render server uses Admin SDK and is not restricted by client Firestore rules.

DEPLOY ORDER
1. Deploy server/index.js and server/catalog.json to the existing Render service and wait for it to become healthy.
2. Publish firestore.rules in Firebase Console.
3. Deploy the four website files (app.js, firebase.js, index.html, style.css).
4. Sign in once. The website calls /api/bootstrap to migrate/initialize the save before loading it.
5. Test a normal crate, a sale, one Gem Crate and a short game run. Confirm balances update and reload the page to confirm they persist.

IMPORTANT SECURITY LIMIT
This is a much stronger economy anti-cheat: the browser cannot directly grant itself currencies, items, crate drops, Index rewards or progression through Firestore. The server validates run tickets and caps rewards using elapsed time and plausible wave/spawn limits. However, the actual 3D combat simulation still runs in the browser, so this is not a fully server-authoritative shooter simulation. A determined cheater could still fake plausible gameplay events within the server's limits. Full gameplay anti-cheat would require moving bot state, damage and kill validation onto the server or using a dedicated authoritative game server.

LEGACY DATA NOTE
The first server bootstrap preserves current Firestore balances and inventory so legitimate existing progress is not wiped. It cannot identify or reverse coins/items that may have been cheated into the save before this update. From the moment the new rules and server are deployed, client-side direct writes to economic fields are denied.
